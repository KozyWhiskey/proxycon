## Setup

Production hosting is Vercel at https://upkeep.vercel.app. The owner confirmed that pushing a new release automatically triggers deployment. Local `.env.local` credentials are not evidence that the corresponding Vercel environment variables are configured; verify the production environment separately before enabling recognition there. Do not push a release solely to test credentials.

Owner rollout preference: keep provider credentials and recognition testing local until the feature works reliably. Do not add provider keys to Vercel or enable hosted recognition as a routine deployment step. Before a hosted pilot, agree on access restrictions for paid recognition; a picked-name session alone does not establish a trusted identity. Normal playgroup access can remain unchanged.

1. Apply `scripts/sql/deck_memories.sql` after `weekend_house.sql` and `roster_phone_sessions.sql`. It is repeatable, preserves Commander decks and old snapshots, marks older duplicate snapshots as earlier memories, imports legacy bucket paths, removes broad snapshot policies, and makes `deck-photos` private. Do not reapply the older public-bucket policies after this migration.
2. Configure server environment variables below. Never use `NEXT_PUBLIC_` for provider keys, service-role credentials, or cleanup secrets.
3. Deploy a Node runtime allowing 120-second handlers. `sharp` and `heic-convert` are runtime dependencies. Production builds must include their native/WASM assets.
4. Keep the feature disabled until migration is applied. Enable it for one draft using `DECK_MEMORIES_ENABLED=true`.
5. Schedule an authenticated POST to `/api/deck-memories/cleanup` daily. Supply `Authorization: Bearer <DECK_CLEANUP_SECRET>`. This expires 30-day inactive unfinished drafts, abandons unprocessed uploads after a day, and deletes up to 100 queued objects per call. Repeat while a backlog remains; failures remain queued. This is a hosting scheduler, not an app/chat automation.

## Flow and safeguards

- `/tournament/[id]/deck` opens/resumes the current memory; `/decks/limited/[id]` is the editor/shared reader. The tournament link follows active match information. My decks includes a separate Limited section; shared memories are discoverable on the tournament.
- Upload authorization allocates an owned record and signed token. No arbitrary source URLs are accepted. HEIC conversion uses libheif through `heic-convert`; accepted formats are decoded, orientation normalized, and metadata stripped before retention. The original is queued for removal. Display uses a high-resolution normalized copy; recognition uses a copy bounded to 3,000 pixels.
- Both calls are independent and concurrent. Per-provider results persist. Retry targets only a failed/interrupted provider in its existing comparison group, with a new idempotency key and reservation. Successful provider results remain unchanged.
- Suggestions are derived from observations against the current corrected list. New evidence never mutates the final card list. Comparisons use canonical identity and quantity; spatial conflicts are marked for review. Look closer uses a crop, recorded as a separate group and never presented as independent agreement.
- Edits autosave after a short pause. Saves use optimistic revision checks and one SQL transaction. The browser warns about unsaved edits on exit. A stale-tab error offers reloading the saved deck. Save responses cannot replace edits made while that save was in flight.
- Agreement is evidence, not verification. Unreadable names, covered cards, foil glare, and hidden quantities still need player review. Models do not enforce legality or fill to 40.
- Endpoints use the current profile, RLS, and server checks. Service-role work starts only after owner validation. Service credentials and raw provider failures never enter client responses.
- Spending records survive memory/photo deletion, preventing delete-and-recreate limit bypasses. Failed/interrupted requests retain conservative reservations when billing is unknown. No automatic paid retries.
- Photo URLs expire in ten minutes. Unsharing stops new grants; existing grants remain valid until expiry. Photo removal queues object deletion without removing saved card rows.

## Gemini API investigation and coordinate fix · 26 October 2026

Read-only hosted attempt inspection found the latest Gemini retry ready in 13.653s, following an older generic failure after about 41s. Its original exception was not retained and cannot be reconstructed. Local control tests reproduced a distinct failure twice on the cube photo: Gemini finished with `stop`, but returned region coordinates above 1; strict observation validation rejected the whole reading. The installed Google SDK also drops numeric/array bounds in its OpenAPI schema conversion. Experiments restoring bounds or using responseJsonSchema received HTTP 400 and were removed; the final implementation retains the existing supported SDK transport.

The Gemini adapter now requests Google's documented `[ymin,xmin,ymax,xmax]` integer box convention on a 0–1000 grid and explicitly converts it to the common 0–1 x/y/width/height observation format. It rejects out-of-range, inverted, incomplete and zero-area boxes rather than guessing units or clamping values. Names/counts remain strictly validated; independent readings, provider selection, token accounting and no automatic paid retries are preserved. Google attempts record prompt version `deck-memory-v2-google-boxes`. The evaluation harness uses the same provider-specific prompt/schema and normalization.

Final live fixture checks completed successfully: cube 10.613s (25/25 provisionally labeled names and quantities), draft 10.641s (20/20 names, 16/20 quantities). These measure only labeled entries; extra predictions and evidence boxes still require adjudication, and two photos do not establish precision or release reliability. Recommendation: retain Gemini as an optional pilot reader, continue comparing corrected deck outcomes, and do not interpret provider agreement as verification. No model defaults, hosted keys, saved player cards, or release deployments were changed.

New failures retain elapsed time and bounded diagnostics (finish reason, HTTP status, known schema paths/codes). Raw values, images, URLs, keys and full provider responses are excluded. Categories now distinguish upstream, connection, request configuration, access, throttling, timeout, truncation and validation errors. `npm run test:deck-memory-reader` mocks the actual SDK transport and validates boxes, canonical normalization, malformed responses, privacy-safe diagnostics and no automatic retries. Its opt-in `--live` mode uses Gemini only and never writes player data. Source: [Google image understanding](https://ai.google.dev/gemini-api/docs/image-understanding).
